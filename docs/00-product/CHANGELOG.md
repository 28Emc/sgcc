# Version Format

SGCC seguirá Semantic Versioning:

```text
MAJOR.MINOR.PATCH
```

Ejemplo:

```text
1.0.0
```

Donde:

## MAJOR

Cambios incompatibles o grandes evoluciones del producto.

Ejemplo:

```text
1.x.x → 2.x.x
```

## MINOR

Nuevas funcionalidades compatibles.

Ejemplo:

```text
1.0.x → 1.1.x
```

## PATCH

Correcciones y mejoras menores.

Ejemplo:

```text
1.0.0 → 1.0.1
```

# Change Categories

Los cambios deberán clasificarse usando estas categorías:

## Added

Nueva funcionalidad o capacidad.

Ejemplo:

```text
Added tenant portal module.
```

## Changed

Modificación de una funcionalidad existente.

Ejemplo:

```text
Changed settlement calculation rules.
```

## Deprecated

Funcionalidad que será retirada.

Ejemplo:

```text
Deprecated legacy export format.
```

## Removed

Funcionalidad eliminada.

Ejemplo:

```text
Removed unused billing workflow.
```

## Fixed

Corrección de errores.

Ejemplo:

```text
Fixed incorrect consumption calculation.
```

## Security

Cambios relacionados con seguridad.

Ejemplo:

```text
Added authentication improvements.
```

# Maintenance Rules

Cada cambio relevante debe actualizar este archivo.

No se registrarán:

- Cambios internos triviales.
- Refactors menores sin impacto.
- Cambios experimentales descartados.

Se registrarán cambios que afecten:

- Producto.
- Usuario.
- Arquitectura.
- Datos.
- Seguridad.
